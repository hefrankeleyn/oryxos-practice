#### 2. 功能角度：都有 Agent 执行闭环，入口和组织方式有所不同

| 比较维度 | Hermes Agent | OryxOS |
| --- | --- | --- |
| 本次使用入口 | CLI 中直接提出任务，观察工具执行与结果。 | 通过 API 配置命名 Agent、Provider 和通知渠道，触发执行并查看记录，也可访问管理台。 |
| 工具执行 | 本次验证文件写入、读取和 Shell 检查，模型根据任务组织多步操作。 | 本次验证模型请求 notify 工具并把消息发送到飞书，调用过程可查询审计记录。 |
| 长期记忆 | 实际验证了保存用户约定，并在新会话使用。 | 官方文档和代码包含长期记忆能力，但本次没有做对应的跨会话实验，不能据此断言没有或弱于 Hermes。 |
| 技能复用 | 实际验证了将方法保存为 SKILL.md，并加载用于新任务。 | 官方文档描述共享 Skill 与 Agent 绑定、按需读取正文；本次没有进行同等复用实验。 |
| 任务管理 | 本次体验以交互式完成任务为主；不能由此推断 Hermes 只有 CLI 或不支持自动化。 | 本次体现了 Agent、Provider、渠道、执行记录的集中配置；源码还包含调度入口，但本次只手动触发，没有验收定时任务。 |

两者共同的关键能力是：模型决定下一步及工具参数，运行时实际执行工具，把结果反馈给模型，直至完成任务。它们并不只是给大模型增加一个聊天界面。

#### 3. 技术架构角度：不同技术栈承担相似的运行时职责

Hermes 的 Agent 核心使用 Python，本次源码可看到 `run_agent.py` 中的 `AIAgent`，以及独立的 Memory、文件操作、Skill 管理工具；安装过程还准备了 Node 和终端/Web 界面资源。长期记忆和技能由外部存储管理，并在需要时提供给模型。跨会话记住目录并不意味着 DeepSeek 的模型参数被重新训练。

OryxOS 使用 Java 21、Spring Boot 和 Maven 多模块。本地官方源码中，`AgentService` 组织执行，`ReActLoop` 负责模型与工具的循环，`ToolExecutor` 承担工具执行及审计。文档描述同步流程配合 virtual thread；Agent 通过 AGENT.md 等配置表达任务，REST API、管理台及调度入口围绕运行时组织。第一题的实际审计记录为这一执行链路提供了具体证据。

我的理解是，模型提供决策能力，而运行时负责会话、上下文、工具执行、结果反馈和状态保存。两者都需要处理这些问题，差别在模块划分、配置方式、技术生态和治理能力的组织上。不能仅根据 Python 或 Java 判断性能、安全性或生产成熟度，本次也没有做并发压测和安全评估。

#### 4. 企业价值角度：根据业务需求选择，而不是给项目简单排名

| 企业需求 | 本次实践带来的判断 |
| --- | --- |
| 快速验证一个任务能否交给 Agent | Hermes 的交互式工具记录、Memory 和 Skill 复用便于快速试验；这次从自然语言任务到真实文件产物的过程很直观。 |
| 把 Agent 接入现有业务系统 | OryxOS 的 API、命名 Agent、通知渠道和执行记录提供了可接入的组织方式；第一题已跑通飞书通知链路。Hermes 能否满足相同集成需求，应另做接口与部署验证。 |
| 团队维护与二次开发 | Java/Spring 团队可以结合现有经验评估 OryxOS；Python 团队可以评估 Hermes 的核心代码和工具扩展方式。熟悉技术栈有助于维护，但不代替功能验收。 |
| 权限、审计与上线治理 | OryxOS 本次已看到调用审计，Hermes 本次看到交互确认与执行记录；两者是否满足组织权限、敏感数据处理、故障恢复和合规要求，仍需专项验证。 |

本地运行 Agent 也不等于数据完全不出本机：本次两者都使用 DeepSeek API，模型请求仍会发送到外部服务。因此，企业落地时需要分别考虑运行时部署位置、模型服务位置、工具权限和发送给模型的数据范围。

#### 5. 我的学习结论

通过实操，我把三个概念区分开了：**Tool 是执行动作的能力，Memory 保存跨会话仍有效的信息，Skill 保存可复用的做事方法。** 模型负责选择和组织，运行时负责执行与反馈。

我对 Agent OS 的理解也更具体了：当 Agent 从一次个人实验变成业务系统里的持续任务，就需要进一步管理配置、触发方式、权限、状态、审计与维护。OryxOS 的 API、渠道和执行记录让我看到了这类组织方式；Hermes 的 Memory 与 Skill 实验则让我看到了经验和方法如何被保存并复用。两者有重叠，不能简单分成“个人工具”和“企业平台”，更不能仅凭名称认定谁功能更强。

此外，模型解释也需要验证。Skill 实验中文件实际为 67 字节，Hermes 却把正文解释成 60 字节；独立读取确认应为 66 字节正文加 1 字节换行。这提醒我：应依据工具记录和实际产物验收，而不是只看自然语言结论。
