# Feature Specification: 项目基础设施初始化

**Feature Branch**: `main`（用户明确要求直接在主分支继续）
**Created**: 2026-11-04
**Status**: In progress
**Input**: 提交全部现有改动后，使用 oryxos-init 补齐当前项目基础设施。

## User Scenarios & Testing

### User Story 1 - 可诊断的服务运行（Priority: P1）
运维人员能在隔离环境启动现有服务、检查健康和指标、关联同一请求的日志，且不影响命令行使用。
**Independent Test**: 临时工作区启动服务，检查健康与指标；执行原有 CLI 测试。
**Acceptance Scenarios**:
1. 默认启动后，管理接口只在本机独立入口可达，健康检查不访问付费模型。
2. 一次成功或失败请求的日志具有相同关联标识，下一请求不继承该标识；敏感值不进入日志。
3. 结构化日志可解析，CLI 的正常输出与诊断输出仍相互分离。

### User Story 2 - 一致的接口基础契约（Priority: P1）
接口开发者能复用统一响应、错误映射和输入约束，并在本地按需查看接口文档。
**Independent Test**: 仅在测试源码注册控制器，验证成功、参数错误、404、500、503和504的响应与状态。
**Acceptance Scenarios**:
1. 成功与错误使用同一信封，不返回原始异常或堆栈，不把失败伪装为成功状态。
2. 参数约束按字节长度处理多字节字符，文档、监控输出不被业务响应包装改写。
3. 正常默认配置不开放文档页面，隔离文档配置可打开规范和页面。

### User Story 3 - 可重复的工程质量检查（Priority: P1）
开发者能用一致的命令验证格式、编码约束、静态安全与依赖漏洞；提交前检查不修改暂存内容。
**Independent Test**: 正常源码检查通过，隔离违规样例使对应检查失败；扫描缺少数据时明确失败。
**Acceptance Scenarios**:
1. 既有源码采用统一格式后仍通过原测试；再次格式化不产生差异。
2. 自动检查报告范围与未覆盖项，工具不兼容或漏洞库缺失不算通过。
3. 本地 hook 和 CI 检查具有相同基础规则，不自动改代码、提交或发布。

### Edge Cases
- CLI 非 Web 模式、未知路由、错误分派及同一线程连续请求。
- 中文/emoji 超过消息字节上限；输入异常包含虚构密钥。
- 漏洞库不可用、工具链与Java语法不兼容、部分暂存与已有hook。

## Requirements

### Functional Requirements
- **FR-001**: 保持已有九模块、运行入口和审计数据行为，不实现新的业务端点。
- **FR-002**: 提供可读/结构化日志及请求关联，保证敏感值不泄露和上下文清理。
- **FR-003**: 提供受限健康、信息和指标入口，普通配置不开启文档页面。
- **FR-004**: 公共响应包含 code/message/data/timestamp，HTTP状态准确；覆盖400/404/500/503/504。
- **FR-005**: 为消息提供32KiB UTF-8字节限制的可复用校验；已有同步执行模型保持不变。
- **FR-006**: 执行统一格式、编码规约、代码安全、敏感信息和依赖漏洞检查，违规返回失败。
- **FR-007**: 阿里规则须如实报告自动覆盖；不兼容的官方插件不以跳过方式标为完成。
- **FR-008**: 提供CI和不修改索引的提交前检查，分别记录配置、本地执行和远端状态。
- **FR-009**: 所有运行验证使用可丢弃数据、回环端口和可控fixture。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 原有可控测试全部通过，外部模型验收保持单独口径。
- **SC-002**: 规定的成功及五类错误响应测试通过，敏感样例在响应与日志中均不可见。
- **SC-003**: 默认与文档模式分别验证，非授权入口不可见；管理探针不调用真实模型。
- **SC-004**: 格式与至少一种静态缺陷的负向fixture使检查失败；重复格式化没有新差异。
- **SC-005**: 每项质量检查都有真实结果或明确未完成原因，不以配置文件存在代替验证。

## Assumptions
- 本次为本地初始化，不推送、部署或设置远端分支保护；初始未提交改动已保存为两个主分支提交。
- 保留业务API原定60秒超时错误契约；本次仅提供公共映射，真实Agent请求的执行期限随业务端点接入验证，不把Servlet异步配置冒充同步硬超时。
- 不新增管理看板、业务示例控制器、用户认证或新的数据库表。
- 用户于2026-11-04确认：阿里规约使用PMD 7 + Checkstyle兼容映射并记录覆盖缺口，其他条款保留人工清单；NVD漏洞扫描保留待配置，不标记为通过。
