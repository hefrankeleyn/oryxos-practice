### Session 2026-10-29

- Q: 本功能完成时，关闭并重新启动 OryxOS 后，是否必须恢复之前的对话历史？ → A: 采用推荐选项 A，只保证进程内会话，跨重启恢复留到后续功能；LLM/Tool 审计仍须持久保存。

- Q: 本功能完成时，你希望必须实际接通哪些模型服务？ → A: 采用推荐选项 A，真实验收 DeepSeek 的对话与工具闭环；用两个可区分的可控目标验证配置选择，Kimi 的真实接入留到后续核心阶段。

- Q: 如果模型或工具调用的审计记录写入失败，程序是否应停止本次处理中的后续调用？ → A: 采用推荐选项 A，可提前检测的审计故障阻止新调用；调用后写入失败则报告失败、停止后续调用，不自动重放已发生的操作，不宣称审计完整。

- Q: 修改配置文件后，你希望这些修改什么时候生效？ → A: 采用推荐选项 A，Provider、模型、工具列表及迭代上限等运行配置重启生效；AGENT.md 正文和 Bootstrap 引导文件每轮重新读取。

## User Scenarios & Testing *(mandatory)*

故事按用户价值和依赖组织，全部为本功能必选要求；优先级不意味着可推迟审计或安全。
各故事可用隔离的可控模型响应、测试工具和可丢弃存储独立核对，不依赖完整 Memory、MCP 或 Web。
以下均为未来实现验收要求，本轮不运行。真实 Provider 验收与可控响应验证分别记录。

### User Story 1 - 初始化并与 Agent 多轮对话 (Priority: P1)

作为开发者，我希望初始化必要工作区，提供 Agent 定义及外部凭证后，从终端连续对话，
让 Agent 结合本次会话的历史回答，直到我退出。

**Why this priority**: 这是最小可用入口，也是后续工具闭环的底座。

**Independent Test**: 在临时目录初始化两次，加载有效 Agent，发送三条有关联的消息，
核对历史与回复的关联并退出；重启后可创建新会话，不要求恢复旧对话，同时核对已写入的审计仍可读取。修改运行配置后验证重启生效、修改正文/Bootstrap 后验证下一轮生效；完成 21 个交互轮后继续输入，核对下一次模型输入只包含最近默认 20 个已完成轮、系统指令与当前处理链，进程内原始历史仍完整。

**Acceptance Scenarios**:

1. **Given** 工作区尚不存在，**When** 执行初始化，**Then** 必要目录与上下文文件可用；再次初始化不覆盖用户已有内容。
2. **Given** 有效 Agent 目录及外部配置，**When** 选择该 Agent 开始对话，**Then** 使用其运行配置和指令，无需修改业务代码。
3. **Given** 同一会话先说明一项事实，**When** 后续要求基于该事实回答，**Then** 按顺序提供应保留的历史，每条实际发生的消息只注入一次。
4. **Given** 两个不同会话身份，**When** 分别发送不同事实，**Then** 一方的历史不混入另一方。
5. **Given** 交互正在进行，**When** 开发者退出，**Then** 结束输入循环，不再发起新调用。
6. **Given** 已发生对话并正常退出进程，**When** 重新启动并开始新会话，**Then** 能进行新的对话，不要求恢复旧对话；已成功写入的调用审计仍可读取。
7. **Given** 运行期间修改 Provider、模型、工具列表或迭代上限等运行配置，**When** 不重启继续对话，**Then** 仍使用原配置；重启后加载并校验新配置。
8. **Given** 修改 AGENT.md 正文或已引用的 Bootstrap 文件，**When** 发起下一轮模型调用，**Then** 读取修改后的内容，不要求重启；本条不新增文件引用或运行配置的热更新能力。
9. **Given** 默认配置下已有 21 个完整交互轮，**When** 继续对话并组装下一次模型输入，**Then** 已完成历史仅包含最近 20 个完整轮，系统指令和当前正在处理的完整工具链仍保留；进程内原始历史不删除。
10. **Given** 历史轮数上限配置已按重启规则生效，**When** 历史超过该上限，**Then** 仅模型输入按新上限保留完整交互轮，不拆散工具请求与结果，进程内原始历史不因此删除。

### User Story 2 - 配置选择 Provider/模型并定位错误 (Priority: P1)

作为开发者，我希望通过配置选择模型服务和模型，发生错误时知道应修正哪里，同时不暴露凭证。

**Why this priority**: 目标选择正确、错误可定位是对话入口可靠可用的前提。

**Independent Test**: 用两组可区分的可控响应验证配置选择，再注入缺失密钥、未知 Provider、
非法配置和调用失败；另以真实 DeepSeek 验证连续对话与测试工具闭环，结果与可控测试分别记录。

**Acceptance Scenarios**:

1. **Given** 两组有效 Provider/模型配置，**When** 分别加载后请求，**Then** 请求到达指定目标，未选择的目标不接收请求；Provider/模型配置修改后重启才生效。
2. **Given** 必填配置缺失、格式非法或 Provider 未配置，**When** 尝试对话，**Then** 指出出错字段或来源，不向无效目标请求，不打印凭证值。
3. **Given** 模型服务拒绝请求、不可达或超时，**When** 调用失败，**Then** 返回可定位的失败，不冒充正常回答，不自动换到其他 Provider。
4. **Given** 对方错误信息含敏感凭证，**When** 反馈或记录错误，**Then** 错误仍可定位且凭证不出现在终端、日志或审计中。

5. **Given** 已配置有效的 DeepSeek 凭证与支持工具调用的模型，**When** 连续对话并请求无外部副作用的测试工具，**Then** 真实完成模型调用、工具执行、结果回填和最终回复，并有持久审计证据；不以可控响应代替真实验收。

### User Story 3 - 完成受控工具闭环 (Priority: P1)

作为开发者，我希望模型提出工具请求后，由运行时执行允许的工具并回填结果，让模型继续处理；
失败和无法收敛时有明确结果。

**Why this priority**: 这是本功能区别于普通模型对话的核心行为。

**Independent Test**: 可控模型依次请求工具、根据结果提出另一请求、最终回复。
测试工具只计算或返回固定数据，通过测试观察统计执行次数，不访问外部系统或修改用户文件。
拒绝路径用受控测试验证，不执行真实危险操作。

**Acceptance Scenarios**:

1. **Given** 模型请求一个允许的测试工具，**When** 处理请求，**Then** 工具执行一次，结果关联原请求，下一次模型调用看到结果并继续至最终回答。
2. **Given** 存在连续两次独立请求，**When** 执行循环，**Then** 两次结果各自对应原请求且顺序正确；一次响应内多个工具请求顺序执行，不并行。
3. **Given** 同一次请求被框架回调或重复分发，**When** 再次处理，**Then** 不重复执行；独立的新请求不因名称或参数相同而被误删。
4. **Given** 工具不存在、未向当前 Agent 开放、参数非法或执行失败，**When** 处理请求，**Then** 返回关联的失败，不伪造成功；未授权或参数非法时不执行工具。
5. **Given** Sandbox 拒绝一个受控测试请求，**When** 处理请求，**Then** 操作未发生，拒绝结果可定位且有失败审计。
6. **Given** 模型持续请求工具，**When** 达到配置的最大迭代次数，**Then** 停止本次处理并反馈上限原因，不发起下一轮模型或工具调用。

### User Story 4 - 追溯模型和工具调用 (Priority: P1)

作为开发者或运维人员，我希望能从本地持久记录确认调用目标、结果和失败原因，不依赖日志反推。

**Why this priority**: 审计是宪章必选约束，与闭环一起验收，不能随会话持久化延后。

**Independent Test**: 分别触发模型成功、模型失败、工具成功、工具失败、Sandbox 拒绝，
直接检查可丢弃存储中的审计记录；不新增查询命令、API 或页面。另分别验证调用前审计不可用及调用后写入失败，核对新调用被阻止、后续调用停止且已发生操作不被自动重放。

**Acceptance Scenarios**:

1. **Given** 审计存储正常，**When** 发生上述五类路径，**Then** 每次调用或拒绝均有可关联的持久记录，结果可区分，拒绝不被记录为执行成功。
2. **Given** 进程退出，**When** 检查审计数据，**Then** 已成功写入的记录仍可读取，不取决于会话是否支持跨重启恢复。
3. **Given** 调用含敏感配置或参数，**When** 保存审计，**Then** 可定位会话、目标和结果，但不含凭证、完整 Prompt、敏感工具参数或未经脱敏的模型响应。
4. **Given** 发起调用前已检测到审计不可用，**When** 尝试发起模型或工具调用，**Then** 阻止新调用并反馈审计故障，不宣称审计完成、不以日志代替落库。
5. **Given** 模型或工具调用已发生但随后审计写入失败，**When** 处理该故障，**Then** 报告本次处理失败、停止后续调用、不自动重放已发生操作，也不宣称审计完整；不得声称已撤销远程操作。

### Edge Cases

- 工作区不可写或已有用户内容：不覆盖原文件，不宣称初始化成功，错误可定位。
- Agent 缺失、frontmatter 非法或引用无效：不带错误配置继续请求，不输出凭证。
- 空输入不应无故触发模型调用；空模型响应不能冒充正常答案。
- 请求重复分发与合法独立请求必须区分；本功能不承诺跨重启的分布式 exactly-once。
- 工具结果不得串到其他请求；裁剪模型输入时不能破坏工具请求与结果的配对。
- 失败反馈、重试和持续工具请求不得绕过迭代上限；重试需区分请求与实际尝试并可追溯，不能无条件重放。
- Provider 未返回 token 用量时不编造数据，应区分未知与实际为零；字段表达留给 Plan。
- 配置校验失败不等于已发生远程模型调用；事件分类留给 Plan。
- 审计故障可提前检测时阻止新调用；操作后写入失败则停止后续调用，不自动重放，也不承诺回滚已发生的远程操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 提供初始化与交互对话所必需的最小 CLI 能力；初始化幂等，不覆盖已有工作区文件。验收：US1-1、US1-5。
- **FR-002**: 从所选 Agent 目录加载运行配置、任务指令及必要 Bootstrap 上下文，无需修改业务代码。验收：US1-2。
- **FR-003**: 按渠道、用户和 Agent 区分会话身份，保留进程内有序原始历史，不重复注入、不混入其他会话；模型输入仅保留最近默认 20 个已完成交互轮，上限可配置。一轮为一次用户输入至最终回复，包含中间工具请求和结果；系统指令及当前正在处理的完整工具链不因历史轮数限制被截断。验收：US1-3、US1-4、US1-9、US1-10。
- **FR-004**: 本功能仅保证进程内会话，不要求关闭并重启后恢复对话；跨重启恢复留到后续功能，调用审计仍须持久保存。运行配置修改后重启生效，AGENT.md 正文与已引用的 Bootstrap 每轮重读；历史限制只裁剪模型输入，不删除进程内原始历史，按 FR-003 保留完整轮与当前处理链。验收：US1-6 至 US1-10。
- **FR-005**: 配置选择 Provider 和模型，不自动猜测目标；以两个可区分的可控目标验证选择正确性，并真实验收 DeepSeek 的对话与工具闭环。Kimi 真实接入留给后续核心阶段，可控与真实证据分开报告。验收：US2-1、US2-5、SC-003。
- **FR-006**: 校验必要配置和凭证引用；错误指出字段或来源，不泄露凭证，不触发无效目标请求。验收：US2-2。
- **FR-007**: 模型失败提供可定位、脱敏的反馈，不伪装成功，不自动切换 Provider。验收：US2-3、US2-4。
- **FR-008**: 完成模型工具请求、运行时执行、结果关联回填、继续处理及最终返回。验收：US3-1、US3-2。
- **FR-009**: 同一次工具请求不因重复调度被重复执行；独立请求不因名称或参数相同被抑制。验收：US3-3。
- **FR-010**: 未知、未开放、非法参数、执行失败及 Sandbox 拒绝有明确关联反馈；拒绝先于实际操作。验收：US3-4、US3-5。
- **FR-011**: 最大迭代次数可配置，默认 10；达到上限停止并反馈原因；同一响应内多个工具请求顺序执行。验收：US3-2、US3-6。
- **FR-012**: 模型/工具调用及 Sandbox 拒绝均须持久审计，覆盖成功和失败，日志不能替代。验收：US4-1、US4-2。
- **FR-013**: 审计关联会话、调用目标、结果、失败信息和耗时；模型记录包括 Provider、模型及可获得的 token 用量，无需保存完整对话内容。验收：US4-1、US4-3。
- **FR-014**: 凭证不得出现在终端、日志或审计中；日志与审计不保存完整 Prompt、敏感工具参数或未经脱敏的模型响应，错误反馈也不得直接透出敏感原始响应。验收：US2-4、US4-3。
- **FR-015**: 可提前检测的审计故障必须阻止新调用；模型或工具调用后写入失败则报告处理失败、停止后续调用，不自动重放已发生的操作，不伪报已审计或已回滚。修复后的补记或人工处置方式留给 Plan，未核实前不得宣称审计完整。验收：US4-4、US4-5。
- **FR-016**: 测试工具仅用于隔离验证，不提供真实天气、通知、文件修改或远程业务操作；本功能测试不能替代最终核心阶段验收。验收：US3 独立测试及范围核对。

### Key Entities *(include if feature involves data)*

- **Agent 定义与派生 Profile**：名称、运行配置、任务指令和上下文引用；一个目录定义一个 Agent，不独立手写 Profile。
- **Provider/模型选择**：服务标识、模型标识和外部凭证引用；凭证值不进入对话或审计。
- **会话与消息**：会话身份、有序用户消息、模型回复、工具请求及关联结果；本功能只保证进程内保留，不要求跨重启恢复。
- **工具请求与结果**：请求身份、工具名、输入和成功/失败结果；能区分收到请求与实际执行。
- **调用审计**：关联调用的持久证据，表达目标、结果、失败、用量与耗时，独立于会话恢复能力。

### Included / Excluded Scope

**包含**：必要初始化与 Agent/Bootstrap 加载、最小 CLI 多轮对话、Provider/模型配置选择、
工具闭环、去重与停止、错误反馈、安全校验边界、SQLite 调用审计及隔离验收要求。
会话跨重启恢复和 Kimi 真实接入留给后续功能；本功能真实验收 DeepSeek 的对话与工具闭环。

**不包含**：全部 CLI 命令、Profile 管理命令全集、REST/管理台、定时调度、自动路由、Fallback、
熔断、流式输出、多 Agent、并行工具、九个内置工具或 MCP 的完整实现、产品级天气工具、
长期记忆读写/检索、会话跨重启恢复、审计查询界面、容器/microVM 强隔离。测试工具不作为默认向正常用户开放的产品工具。
