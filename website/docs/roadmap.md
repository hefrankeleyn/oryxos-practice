# 路线图

> 慢就是快，克制且聚焦。先把单机的运行时内核做扎实，让"一个节点上运行和管理一群 Agent"这件事真正可用、有人用，再在它之上逐步生长出分布式能力。

| 阶段 | 形态 | 重点 | 状态 |
|---|---|---|---|
| **阶段一** | 单机运行时内核 | 五大核心能力跑通，单节点运行和管理一群 Agent | 🚧 进行中 |

## 阶段二：底座分布式（规划中）

当企业从"一个部门试点"走向"服务全公司"，单机会撞到三件事：扛不住量、扛不住故障、扛不住规模化治理。

演进的核心原则是**实例无状态，状态外置**：

- 会话和短期上下文外置到 Redis 一类的内存存储
- 长期记忆和 Skill 库外置到 PostgreSQL（向量检索可用 pgvector）
- 审计日志和大文件外置到对象存储
- Agent 配置和租户信息外置到配置中心和数据库

在此之上解决多实例的几件事：渠道消息不重复消费、定时任务只在一个实例上执行（分布式锁或租约）、多租户在存储层和请求链路上的隔离。服务注册、限流熔断、链路追踪直接复用 Nacos、Sentinel、Spring Cloud Gateway、SkyWalking 等成熟的 Java 生态方案。

## 阶段三：跨节点 Agent 协作（愿景）

一个企业里有几十上百个 Agent，分散在不同部门、不同机器，甚至延伸到合作伙伴的组织里。一笔大额采购，可能要运维 Agent 确认资源、财务 Agent 核算预算、法务 Agent 审合同。

OryxOS 是单个节点上的 Agent 运行时；连接多个 OryxOS 节点、让 Agent 能跨节点互相发现、可靠委托、共享必要上下文的，是一层专门的 **Agent 通信底座**，对接 A2A 开放协议。两者分开演进，最后合起来，构成完整的"分布式 Agent OS"。
